# 播放控制层重写：阶段 0 设计文档（总览与导引 · v2）

## 本版相对 v1 的变更
1. **状态机升级为 11 状态**：引入自愈核心 `recovering` 状态；拆分 `prebuffering` 与 `rebuffering`；收紧首帧超时兜底门禁（无推进证据则重连）。
2. **事件分界与归因机制**：明确 Attempt ID 用于 Dart 异步续接，引入原生 `openToken` 分界与 URL 归因解决 C 线程事件跨集串扰。
3. **结构化错误模型 (`BackendError`)**：废除粗暴字符串 `contains('403')` 判定；收敛单点解析并剥离 URL；良性日志限定首帧后生效；建立 13 秒端到端硬上限预算表；明确 403/404 仅驱逐 L1 直链缓存而不删 `SourceBinding` 绑定。
4. **接口与契约标准化**：`PlayerBackend.onErrorOccurred` 强类型化为 `Stream<BackendError>`；所有事件携带 `openToken`；`play()`/`pause()` 严格幂等；统一 Session 模型为“每次 open 创建全新独立实例”。
5. **暗坑清单修正与扩充**：暗坑 1 因果标为“待验证”；底层 TLS 库正名为 **mbedTLS 3.5.0**；扩充至 21 项暗坑。
6. **验收场景扩充至 21 个**：修正 TC-05、TC-10、TC-11；新增 TC-15 ~ TC-21 涵盖握手失败重试成功/耗尽、中途假 EOF 断点续接、页面快速退出防泄露、合法慢起播与迟到事件隔离。
7. **架构职责解耦**：将 15s 有效播放统计与历史落盘剥离为独立的 `WatchProgressTracker` 领域服务，不侵入 `PlaybackSession`。新增阶段 1 开工前三大待验证项的探针验证任务。

## 阶段 1 开工前置验证要点提示

依据架构规范，在阶段 1 编写任何生产 `.dart` 代码前，必须先在宿主应用中通过简单的日志探针实测锁定以下 **三大底层待验证事实**：
1. **`player.open()` Future 完成时机**（是派发 IPC 后立即完成，还是握手完成后完成？）；
2. **`Failed to open <url>` 的接收通道**（经由 `stream.error` 还是 Future `catchError`？）；
3. **首帧建联期间各底层流事件的物理先后发生顺序**。
